# Coding with LLMs

His stated workflow changed over time; the wiki keeps both positions with dates.

**Oct 2025 ([interview](../sources/dwarkesh-2025.md))**: autocomplete in code he writes himself; agents bloat code with defensive checks and don't follow his style; vibe-code only boilerplate or code he can test against a version he understands.

> For now, autocomplete is my sweet spot.
> — `raw/interviews/dwarkesh-2025.md`

> I have a bunch of assumptions in my code, and it’s okay.
> — `raw/interviews/dwarkesh-2025.md`

> I had a Python implementation that I fully understand, and I’m just making sure I’m making a more efficient version of it, and I have tests so I feel safer doing that stuff.
> — `raw/interviews/dwarkesh-2025.md`

**Dec 2025 – Apr 2026 ([year in review](../sources/year-in-review-2025.md), [Sequoia summary](../sources/sequoia-ascent-2026.md))**: Claude Code as the first convincing agent; around December 2025 he started delegating larger chunks. He separates vibe coding from agentic engineering:

> Vibe coding raises the floor.
> — `raw/bearblog/sequoia-ascent-2026.md`

> Agentic engineering raises the ceiling.
> — `raw/bearblog/sequoia-ascent-2026.md`

**Tension:** the 2025 “agents produce slop” view versus the 2026 “I trust agents with more of the work” view. Likely both true at their dates; the constant is that someone has to understand and verify the result. [MenuGen](../sources/vibe-coding-menugen.md) shows where vibe coding got stuck for him (deploy, auth, payments, stale docs).
