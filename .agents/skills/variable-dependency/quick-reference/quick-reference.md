# Variable Dependency - Quick Reference

## When to Use

**Use this skill when:**
- Want to create "smart" products that adapt to users/context
- Looking for non-obvious innovations beyond modification
- Current product is one-size-fits-all
- Need ideas for responsive, context-aware behavior

**Don't use when:**
- Haven't defined solution yet (do solution-definition first)
- Want to simplify/reduce (use Subtraction or SCAMPER Eliminate)
- Looking for physical modifications (use SCAMPER Modify)

---

## Core Concept

**Create new relationships between previously independent variables.**

Formula: "[Internal variable] changes as a function of [External/Internal variable]"

Then ask: "What value does this dependency create? For whom?"

---

## Three Types of Dependencies

| Type | What It Means | Example |
|------|--------------|---------|
| **Internal ↔ Internal** | Two product attributes now co-vary | Battery mode varies with charge level |
| **Internal ↔ External** | Product responds to environment/user | Price varies with demand (Uber) |
| **Breaking existing** | Currently linked variables become independent | Screen size independent of phone size (foldable) |

---

## 6-Step Process

1. **Map internal variables** (10-15 product attributes you control)
2. **Map external variables** (8-12 environmental/user conditions)
3. **Build dependency matrix** (internal rows x external columns)
4. **Scan for interesting pairs** - especially unlikely ones
5. **Create virtual products** - describe the dependency in action
6. **Discover value** - who benefits? What problem does it solve?

---

## Quick Variable Categories

**Internal (you control):**
- Product: size, color, speed, capacity, content
- Business: price, terms, availability, features
- Interface: language, complexity, layout, notifications

**External (you don't control):**
- User: age, skill, mood, income, behavior, history
- Time: hour, day, season, elapsed time
- Environment: weather, location, connectivity, device
- Context: social setting, urgency, market conditions

---

## Prompting Questions

- What if [feature] adapted to [user behavior]?
- What if [price/term] varied with [time/context]?
- What if [content] responded to [user characteristic]?
- What if [notification] adjusted to [user state]?
- What's the most unlikely pair? What if I linked them?
- What current dependency should be BROKEN?

---

## Classic Examples

| Product | Dependency | Value |
|---------|-----------|-------|
| Transition lenses | Tint ↔ sunlight | No switching glasses |
| Uber surge pricing | Price ↔ demand | Supply matches demand |
| Auto-brightness | Display ↔ ambient light | Comfortable viewing |
| Anti-lock brakes | Brake pressure ↔ wheel slip | Safe stopping |
| Netflix streaming | Watch time ↔ schedule | Broke time dependency |

## Common Pitfalls

1. **Only obvious pairs** - Push for unlikely combinations
2. **Trivial dependencies** - "Price varies with quantity" already exists
3. **Skipping value discovery** - The dependency isn't the innovation; the discovered value is
4. **Skipping the matrix** - Forces you to consider non-intuitive pairs
5. **Only creating, never breaking** - Breaking dependencies can be equally powerful

---

- Each with value discovered and target user
