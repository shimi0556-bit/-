# Systematic Inventive Thinking (SIT) Framework

## Origins

Systematic Inventive Thinking (SIT) was developed by researchers Genrich Altshuller (TRIZ), Roni Horowitz, and Jacob Goldenberg. It builds on the observation that successful innovations share common patterns—and these patterns can be taught, practiced, and systematically applied.

Unlike brainstorming, which asks "think of anything," SIT provides structured operators that manipulate existing components in specific ways to produce "virtual products"—hypothetical configurations whose value is discovered afterward.

## The Two Foundational Principles

### Closed World Principle

**Statement:** Innovative solutions exist within the Closed World of the product—its components and its immediate environment.

**Implication:** Don't look outside for new resources. Instead, find hidden potential in what you already have.

**The Closed World consists of:**

**Internal components (controlled by the maker):**
- Physical parts and materials
- Software features and algorithms
- Data and information flows
- Processes and workflows
- Channels and interfaces
- Pricing and business model elements

**External components (in the environment, not controlled):**
- Users and their characteristics (age, location, behavior, mood, skill level)
- Environmental conditions (time of day, weather, season, location)
- Infrastructure (networks, roads, regulations, social norms)
- Other products and services in the user's life
- Social context (peers, family, community)

**Why constraints help creativity:**
Without constraints, the search space is infinite and creativity is diffuse. With the Closed World constraint, you're forced to look deeper at what exists, revealing opportunities that unbounded thinking overlooks.

### Function Follows Form

**Statement:** Instead of designing a form (product) to fulfill a function (need), create a new form first, then discover what function it could serve.

**Traditional process (Function → Form):**
1. Identify customer need
2. Design product to meet that need
3. Build and launch

**SIT process (Form → Function):**
1. Take existing product and its Closed World
2. Apply a SIT technique to create a "virtual product" (new configuration)
3. Ask: "What value could this provide? To whom? In what context?"
4. If valuable, develop further

**Why this works:**
- Customers can't articulate needs for products they've never imagined
- Surveys and focus groups optimize for the known, not the unknown
- Many breakthrough innovations were discovered, not designed (Post-it Notes, Velcro, penicillin)
- Breaking "functional fixedness"—the cognitive bias that locks us into seeing things only as they currently are

**The value discovery step is critical:** A virtual product without value discovery is just a weird configuration. The magic happens when you genuinely ask "who could benefit from this?"

## The Five SIT Techniques

### 1. Attribute Dependency (Variable Dependency)

**What it does:** Creates a new relationship between two variables that were previously independent, or breaks an existing dependency.

**Process:**
1. List internal variables (attributes the maker controls)
2. List external variables (attributes in the environment)
3. Build a dependency matrix (internal × internal, internal × external)
4. For each pair, ask: "What if [Variable A] changed as a function of [Variable B]?"
5. Evaluate the virtual product: What value does this dependency create?

**Types of new dependencies:**
- **Internal ↔ Internal:** Two product attributes that now co-vary (e.g., color changes with temperature)
- **Internal ↔ External:** A product attribute that responds to an environmental condition (e.g., price changes with demand)
- **Breaking existing dependency:** Two variables that are currently linked become independent (e.g., phone size no longer tied to screen size—foldable phones)

**Classic examples:**
- Transition lenses: Lens tint depends on sunlight intensity (internal ↔ external)
- Surge pricing: Price depends on demand level (internal ↔ external)
- Baby bottle thermometer strip: Color depends on temperature (internal ↔ external)
- Anti-lock brakes: Brake pressure depends on wheel slip (internal ↔ internal)

### 2. Subtraction

**What it does:** Removes a seemingly essential component from the product or service.

**Process:**
1. List all components of the product/service
2. Select a component that seems essential (not a trivial part)
3. Remove it completely
4. Ask: "What product remains? How could it still provide value? What NEW value might emerge?"

**Key insight:** The more essential the removed component seems, the more interesting the virtual product tends to be. Removing trivial components produces trivial innovations.

**Classic examples:**
- Walkman (Sony): Removed the recording function from a cassette player → portable music
- Contact lenses: Removed the frame from glasses → comfort, aesthetics
- Self-service checkout: Removed the cashier → speed, lower cost
- Budget airlines: Removed meals, seat assignments, lounges → lower price

### 3. Multiplication

**What it does:** Copies an existing component but modifies the copy along at least one dimension.

**Process:**
1. Select a component to copy
2. Create a copy that differs on one or more attributes (size, location, timing, intensity, target)
3. Ask: "What value does the interaction between original and copy create?"

**Key insight:** The copy must differ from the original. An identical copy just means "more of the same." The modification is what creates innovation.

**Classic examples:**
- Dual-camera phones: Two lenses, different focal lengths → depth perception, zoom
- A/B testing: Two versions of a page, different content → data-driven optimization
- Dual-SIM phones: Two SIM slots → personal and work on one device
- Progressive lenses: Multiple focal points in one lens → no switching glasses

### 4. Division

**What it does:** Breaks a component, the product, or a process into parts and reorganizes them.

**Three types of division:**
- **Physical division:** Split a physical component into separate pieces
- **Functional division:** Separate functions that were bundled together
- **Preserving division:** Create smaller identical units from the whole

**Process:**
1. Select a component or the product itself
2. Divide it into parts
3. Reorganize the parts in space, time, or control
4. Ask: "What value does this reorganization create?"

**Classic examples:**
- Carry-on vs checked luggage: Divided luggage by need (immediate vs later)
- Modular furniture (IKEA): Divided furniture into user-assembled parts → flat-pack shipping
- Split air conditioning: Divided compressor (outside) from blower (inside) → quieter, more efficient
- Course modules (edX, Coursera): Divided courses into micro-units → flexible learning

### 5. Task Unification

**What it does:** Assigns an additional task to an existing component. The component keeps its original function and gains a new one.

**Process:**
1. List all internal and external components
2. For each, ask: "What additional task could this component perform?"
3. Consider both internal components (product parts) and external components (users, environment) as candidates
4. Ask: "What value does this dual-purpose component create?"

**Key insight:** The most powerful task unifications assign tasks to external components—things the maker doesn't control but that are already present.

**Classic examples:**
- Waze: Users (external component) also serve as traffic sensors → real-time traffic data
- Amazon reviews: Buyers (external) also serve as product evaluators → social proof
- Solar roads: Roads (external infrastructure) also generate electricity → dual-purpose infrastructure
- Fitbit: Watch (tells time) also tracks health → unified device

## Using SIT with the Innovation Workflow

### Input from Solution Definition
- **PRFAQ** provides the vision and customer context for evaluating virtual products
- **Closed World map** provides the components to manipulate
- **Customer pains** help identify which virtual products address real problems

### Output to Idea Evaluation
- Virtual products with discovered value propositions
- Ideas grounded in existing components (inherently more feasible)
- Surprising configurations that challenge assumptions

### Complementing SCAMPER
- SCAMPER modifies components to improve toward known goals
- SIT creates new configurations and discovers unknown value
- Using both produces the most diverse and complete idea portfolio
- Run SCAMPER first (familiar, productive), then SIT (deeper, more surprising)

## When SIT Is Most Powerful

SIT tends to produce its most breakthrough results when:
- The product/service is mature and incremental improvements have plateaued
- Brainstorming and SCAMPER yield only "more of the same"
- The team is stuck in functional fixedness ("this component can only do X")
- The market has converged on similar offerings (need genuine differentiation)
- You suspect there are non-obvious innovations hiding in plain sight
