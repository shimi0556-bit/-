# Ideation SIT - Quick Reference

## When to Use

**Use this skill when:**
- Completed solution-definition (have PRFAQ + Closed World)
- Need to discover non-obvious innovations beyond SCAMPER
- Want innovations grounded in existing components
- Ready for systematic creativity using Function Follows Form

**Don't use when:**
- Haven't defined solution vision yet (do solution-definition first)
- Just need one focused technique (use individual SIT technique skills)
- Looking for incremental improvements only (SCAMPER may suffice)

---

## Two Core Principles

### 1. Closed World Principle
Innovate using components that already exist within the product and its immediate environment. Don't add external resources—reconfigure what's there.

### 2. Function Follows Form
Don't start with "what do customers need?" Start by creating virtual products (new configurations), THEN ask "what value could this provide?"

## Five SIT Techniques

| Technique | What It Does | Key Question |
|-----------|-------------|--------------|
| **Variable Dependency** | Links previously independent variables | "What if [A] changed based on [B]?" |
| **Subtraction** | Removes seemingly essential component | "What if we removed [X]? How would it still work?" |
| **Multiplication** | Copies a component with modifications | "What if there were two versions of [X], each tuned differently?" |
| **Division** | Breaks component into reorganizable parts | "What if [X] was split into pieces distributed in space or time?" |
| **Task Unification** | Gives existing component a new job | "What if [X] also performed [Y]'s function?" |

## Function Follows Form Process

For each virtual product you create:
1. **Manipulate:** Apply technique to create new configuration
2. **Imagine:** What does this look like? How does it behave?
3. **Discover value:** Who benefits? What problem does it solve?
4. **Capture:** Record the idea with its value proposition

---

## SIT vs SCAMPER

| | SCAMPER | SIT |
|--|---------|-----|
| Direction | Function → Form | Form → Function |
| Approach | "How can I modify this?" | "What virtual product emerges?" |
| Strength | Systematic modification | Discovers non-obvious innovations |
| Best for | Improving/varying concepts | Finding breakthrough concepts |

**Recommendation:** Use both. SCAMPER for breadth, SIT for depth and surprise.

---

## Technique Selection Guide

**For different goals:**
- **Discover new product behaviors:** Variable Dependency
- **Radical simplification:** Subtraction
- **Product variants/tiers:** Multiplication
- **Modularity/sequencing:** Division
- **Leverage existing assets:** Task Unification

---

## Common Pitfalls

1. **Adding external resources** - Stay in the Closed World
2. **Skipping value discovery** - Always ask "who benefits?"
3. **Rejecting strange configurations** - Strangeness is the signal
4. **Judging too early** - Generate first, evaluate later
5. **Only thinking about current customers** - Virtual products may serve new users
