# brain-graph (אטלס המוח)

Single-file Hebrew (RTL) knowledge graph laid out as a brain: each node lives in the region that matches its psychological function. Source in `brain-graph/src/*.js` + `style.css`, `python3 build.py` inlines everything into `brain-graph/index.html`. No dependencies; PDF support lazy-loads pdf.js from cdnjs only when a PDF is added.

## How it works

- 12 regions (`src/regions.js`): pfc (values/goals), motor (actions), parietal (attention/space), occipital (images), temporal (knowledge/language/people), basal ganglia (habits), ACC (motivation/conflict), amygdala (emotions), hippocampus (memories), hypothalamus (needs), cerebellum (skills), brainstem (energy/state). Geometry is a 1000x700 viewBox, brain front on the right. Deep regions are drawn as an x-ray overlay; surface ones are clipped to the cortex path.
- Layout (`layout.js`): NO region frames and no drawn outline by default - the brain shape must come from the nodes. `buildOrder()` makes one global farthest-point sequence over candidate points (a 15px grid inside the cortex/cerebellum/stem plus outline samples nudged inward, outline weighted x1.6) and splits it per region; a node takes slot i of its region (by creation order), so the first nodes of every region land on the contour and later ones fill inward. Slots are springs; repulsion and link springs are weak. `BG.auraR` sizes each node's radial-gradient glow from region area / count, so the glows merge into a brain-shaped patch even with few nodes. Optional dotted outline + region names are toggles in the regions tab.
- AI (`ai.js`): Anthropic (browser-direct header) or any OpenAI-compatible `/chat/completions`. Four prompts: extract, seeds (where in the graph is the request), work (answer + actions from the visited nodes), organize (batches of 50). Always strict JSON; `parseJSON` strips fences and trailing commas.
- The command flow (`app.js` `runCommand`): seeds → BFS walk (max 26 nodes, depth 2, 4 strongest neighbours each) animated with `BG.pulse` → work call. Activation lives in `node.act/hold` and `edge.act/hold`; `view.js` frame loop eases act toward hold, regions glow by the max act of their nodes. Nothing writes to the graph without the user ticking the proposed actions.
- Without a key: local extractor (word frequency + lexicon in `LEXICON`) and keyword seeds.
- Exports (`exportx.js`): the SVG layers (background, brain, regions, edges, nodes per region) are the single source; PNG and each PSD layer rasterise those SVG strings to canvas. The PSD writer is hand-written (RGB 8-bit, PackBits RLE, Pascal name + `luni` Unicode name block), checked by reading it back with `psd-tools`.

## Notes

- **2026-10-11, Obsidian-style look.** The user said the graph looked like one blob of colour and was not tidy like Obsidian. Causes: the per-node radial-gradient auras blended into a single coloured mass, links were coloured by region and curved, and every extracted node was linked to its source document (a hub per document). Now (`view.js`): auras off by default (`BG.display.glow`), straight thin neutral links, source documents and their links hidden by default (`BG.display.sources`; hidden nodes are also skipped by layout and exports via `BG.isHidden`), flat nodes without outline, label collision culling (`placeLabels`: labels placed by priority, constant ~11px on screen so zooming reveals more, never over another label or node), hover/selection dims everything except the node and its neighbours, and an HTML legend with per-region counts (click = focus). Settings persist in `brain-graph:display`; sliders for node size and link brightness live in the regions tab. Judged from screenshots (128-160 node stress graph + the 24 node demo); the activation glow of the AI walk is unchanged.

- **2026-10-10, dialogue room (no bridge).** First built as a live postMessage bridge (iframe + approval dialog in mapat, an adapter script, multi-peer UI); the user said "no bridge, just make the AIs talk", so all of that was deleted. `src/dialogue.js` + the "שיחה" tab: load export files (psychJournal `items[]` array from the two "המפה הנפשית שלי" apps, or a mapat-hanefesh backup), build a text digest of each journal's data (`journalDigest` / `mapatDigest`), and run round-robin turns where each participant is an AI call whose system prompt contains ONLY its own digest. A participant can carry its own provider/key/model (`BG.ai.call({settings})`), so one can run on Gemini and another on Claude. Optional Atlas participant reads its graph each turn (seeds + `walk`, regions light up). Final moderator call returns `summary`, per-participant text `suggestions` and `atlas_actions` (user ticks them). Journals are never written to; `journalToMapat` converts psychJournal items to the mapat shape for "הכנס לאטלס" (trigger/thought/insight/concept -> belief, body -> need, coping -> behavior; relations = co-occurrence in cases). Tested headless with data exported from the real uploaded apps (A has sample data, B starts empty so a small case set was added), a mocked Anthropic endpoint for Atlas and a mocked OpenAI endpoint for a participant with its own key; verified the second AI's prompt contained none of the first journal's data. The quality of real model conversations is untested.

- **2026-10-10, second pass.** The user rejected the first version: the per-region ellipses/frames and filled silhouette were not what they meant - they wanted the brain to be *made of the values*. Replaced frames with slot-based layout + auras (see above). First attempt (sunflower spiral per ellipse) just clustered nodes in the middle, and per-region farthest-point sequences made neighbouring regions put nodes on the same spot at region borders; the single global sequence fixed that. Judged by screenshots only (24-node demo reads sparse; a 160-node stress set shows the contour clearly).

- **2026-10-09, first version.** Built from the request "mind map that stores knowledge as a graph, ingests documents/links, arranges nodes like a brain by function, AI via API key organises it, marks regions in colour while it walks the memory, works with drawing/editing tools". Related earlier project: `mapat-hanefesh` (Obsidian-style journal, branch `claude/serene-cannon-p1evet`, not merged into main). They are separate apps; no import path between them yet.
- Tested headless with Playwright: mocked Anthropic endpoint (ingest, seeds, work, actions, PSD export), docx via the zip reader, URL via the reader fallback, local extraction, drag-to-reassign, persistence, mobile layout. The real AI call was NOT exercised (no key in the sandbox), only the request shape and headers.
- Bug found while testing: native `Element.append(null)` writes the text "null" — the node panel passed optional children to it. Filter before append (the `h()` helper already skips null).
- Imported/ingested node URLs are restricted to http(s) so `javascript:` links in a crafted backup can't run.
- **2026-10-10, mapat bridge.** `src/mapat.js`: import of a `mapat-hanefesh` backup (concept type -> kind/region: value/belief->pfc, emotion->amy, need->hyp, behavior->action(motor), person->tem; relations keep their Hebrew label and `mtype`; stories become `memory` nodes in the hippocampus linked to every `[[concept]]` they mention) and export back to mapat's format. Verified round-trip against the real mapat page: its own `sanitize()` accepted 26 concepts / 12 relations / 2 stories. Test copy of mapat needed `exportJSON`/`sanitize` exposed from its IIFE; the app itself is untouched (a copy now lives in `mapat-hanefesh/`).
