# אורז לדיסק און קי

המטרה: שמעון מקבל קובץ zip אחד. מחלצים אותו, מעתיקים את התיקייה לדיסק און קי, לוחצים פעמיים על `Start.html`, וזה עובד בכל מחשב עם דפדפן עדכני, בלי אינטרנט ובלי להתקין כלום.

## שלב 1: למצוא כל מה שיוצא לאינטרנט
- מחפשים בקובץ הבנוי כל `http://` ו־`https://`: `grep -oE "https?://[^\"' )]+" dist/*.html | sort | uniq -c`. כתובות בתוך הערות, כמו `w3.org` או מאמרים, לא מזיקות.
- בדרך כלל אלה הגופנים (Google Fonts), ספריות מ־CDN, תמונות, `fetch` ו־`Worker` מקבצים נפרדים.
- **דפדפן שפותח קובץ מהדיסק (`file://`) לא יכול לקרוא קבצים נפרדים עם `fetch`.** לכן הכול צריך להיות בתוך ה־HTML, או בקבצי `<script src>` שיושבים לידו.

## שלב 2: קובץ אחד
- Vite עם `vite-plugin-singlefile` ו־`assetsInlineLimit` גבוה מאוד, כדי שכל תמונה, גופן וקוד ייכנסו לקובץ.
- כמה אפליקציות: `mode` נפרד לכל אחת. **זהירות:** `emptyOutDir` מוחק את `dist`, ולכן קובעים סדר בנייה קבוע.
- גרסה מיוחדת לדיסק און קי, למשל עם נתונים שחושבו מראש: `mode` נפרד עם `outDir` משלו, ומודול וירטואלי שמחזיר את הנתונים רק במצב הזה.

## שלב 3: גופנים מקומיים
- מורידים את ה־CSS של Google Fonts עם User-Agent של Chrome, כדי לקבל woff2:
  `curl -A "Mozilla/5.0 ... Chrome/130" "https://fonts.googleapis.com/css2?family=...&display=swap"`
- שומרים **רק את התת־קבוצות hebrew ו־latin**. גופן משתנה, כמו JetBrains Mono, הוא קובץ אחד לכל המשקלים: `font-weight: 400 700`.
- כותבים `fonts.css` עם `@font-face` לכל קובץ ו־`unicode-range`, מייבאים אותו מקוד ה־JS, ומוחקים את קישורי Google מה־HTML.
- אם מציירים טקסט על canvas, טוענים גם את התת־קבוצה העברית לפני הציור: `document.fonts.load('600 20px "IBM Plex Sans Hebrew"', 'אב AZ 09')`.
- הגופנים של Google הם ברישיון SIL OFL, ולכן מותר לארוז אותם. מציינים את זה בדף הפתיחה.

## שלב 4: מבנה התיקייה
```
Shimotron/
  Start.html              דף פתיחה בעברית: כפתור "שחק", רמות איכות, מקשים, טיפים
  Shimotron-Rally.html    האפליקציה
  Shimotron-Editor.html   כלים נוספים (אם יש)
  README.txt              הוראות בעברית
```
- **שמות קבצים באנגלית בלבד.** שמות בעברית עלולים להשתבש בחילוץ zip ב־Windows ובדיסק FAT32.
- `README.txt` נשמר עם BOM ‏(EF BB BF) ושורות CRLF, כדי שהעברית תוצג נכון בפנקס רשימות.
- `Start.html` מקשר לקבצים שלידו (`href="Shimotron-Rally.html#low"`). קישור עם `#` מעביר הגדרה, למשל רמת איכות.
- בדף הפתיחה כותבים: איזה דפדפן צריך, שהטעינה הראשונה לוקחת כמה שניות, שההתקדמות נשמרת בדפדפן של כל מחשב ולא על הדיסק און קי, ושצריך לחלץ את ה־zip ולא לפתוח מתוכו.

## שלב 5: קובץ zip בלי כלים חיצוניים
כותב zip מינימלי ב־Node, שעובד בכל מחשב: `zlib.deflateRawSync` לכל קובץ, CRC32 מטבלה, כותרת מקומית, ספרייה מרכזית ורשומת סוף. מסמנים שמות UTF-8 (דגל `0x0800`) וקובעים תאריך קבוע, כדי שאותו תוכן ייתן אותו zip. תבנית מלאה נמצאת בפרויקט שימוטרון, ב־`tools/usb.mjs`.

פקודה אחת לכל התהליך: `npm run usb`, שבונה, אופה ואורז.

## שלב 6: בדיקה בלי רשת
```js
await ctx.route('**/*', (r) => {
  const u = r.request().url();
  if (u.startsWith('file:') || u.startsWith('data:') || u.startsWith('blob:')) return r.continue();
  blocked.push(u); return r.abort();
});
```
- **בודקים את ה־zip עצמו:** מחלצים לתיקייה, פותחים את `Start.html`, לוחצים "שחק", ומוודאים שאין בקשות חסומות, שאין שגיאות ושהגופנים נטענו (`document.fonts.check`).
- פותחים גם את שאר הקבצים בתיקייה, למשל העורך.

## מה להגיד לשמעון
- איך מחלצים, מעתיקים ופותחים (שלושה צעדים), ושאפשר לשלוח את הקובץ גם בוואטסאפ או במייל.
- שההתקדמות לא עוברת בין מחשבים, אלא אם בונים ייצוא וייבוא של שמירה.
- כמה זמן לוקחת הטעינה, ומה עוד אי אפשר לשמור מראש (כרטיס המסך מכין את הציור בכל מחשב).

## איך לעשות יותר טוב בפעם הבאה
- **ייצוא וייבוא של שמירה לקובץ**, כדי שהקריירה תעבור עם הדיסק און קי.
- קובץ `.bat` או קיצור דרך שפותח ישר בדפדפן הנכון, כשהדפדפן ברירת המחדל ישן.
- סמל ושם יפה לדף הפתיחה, וצילום מסך מהמשחק בתוך הדף (base64).
- Service Worker ו־PWA, להתקנה כאפליקציה מאתר (לא עובד מ־`file://`).
- בדיקה אוטומטית שה־zip מתחלץ נכון גם ב־Windows, עם שמות ו־BOM.
