# טעינה מהירה

## כלל ראשון: למדוד, לא לנחש
1. **שלבי הטעינה:** רושמים זמן לכל שינוי בטקסט של מסך הטעינה (`MutationObserver` דרך `addInitScript`), ומסכמים לפי סוג שלב.
2. **פרופיילר מעבד:** בונים גרסה לא מכווצת, ומריצים `Profiler` של CDP. מחפשים זמן עצמי גבוה, כמו לולאות רעש, הקצאות, `mergeVertices` או `toNonIndexed`.
3. **גודל מה שנבנה:** משולשים ובתים. אם העולם הבנוי הוא 270 מגה, **שמירה שלו על דיסק תהיה איטית יותר מבנייה.** מסבירים את זה במספרים, ולא מבצעים.
4. **מפרידים בין זמן מעבד לזמן של כרטיס מסך.** בדפדפן בדיקה עם כרטיס מסך מדומה, ההכנה של השיידרים והציור מנופחים.

## 1. תפריט קודם, השאר ברקע
```js
// בסוף הטעינה: מראים את התפריט, ואז מתחילים לבנות ברקע
this._bgBuild = this._preloadIslands((p, t, k, n) => {
  if (this._bgWait) ui.showLoader(`משלים את בניית העולם · ${t}`, p);
  else ui.buildStatus(`בונה את האיים ברקע · ${k + 1}/${n}`);
  return nextFrame();                 // פריים לתפריט בין שלבים
}, true).catch(console.error).finally(() => { this._bgBuild = null; ui.buildStatus(null); });

async _finishWorld() {               // כל "יציאה לדרך" מחכה רק למה שנשאר
  if (!this._bgBuild) return;
  this._bgWait = true; ui.showLoader(...);
  try { await this._bgBuild; } finally { this._bgWait = false; }
}
```
- **בנייה ברקע לא עוצרת את הציור**, ולא משנה שמיים, מים או הגדרות גלובליות. אלה נקבעים כשהאי נכנס למשחק (`resume`).
- **כל נקודת כניסה** (מירוץ, סיור, מעבר בין איים) קוראת קודם ל־`_finishWorld`, ואז אין שתי בניות במקביל.
- ללולאה שבונה ברקע מוסיפים בדיקה "כבר נבנה?" לפני כל פריט.
- **אם שמעון ביקש קודם שהכול ייטען ביחד, שואלים אותו לפני שמשנים.** מסבירים ש"ביחד" עדיין מובטח לפני הנסיעה.

## 2. חישוב מראש לתוך הקובץ
- מתאים לחישובים **כבדים ודטרמיניסטיים עם פלט קטן**: תוכניות מסלול, גבהי קרקע, מפות קרקע. לא מתאים לגאומטריה ענקית.
- **מפתח שכולל כל קלט:** זרע, גודל, תוכנית, אורך שביל, **וקצוות הגשרים**. גם קלט שנראה לא קשור. אצלנו רשת מפה שהייתה תלויה ברמת האיכות הזיזה את הגשרים.
- **חתימה של קבצי המקור:** הבנייה מסרבת להשתמש בנתונים שנאפו מקוד ישן (`sourceHash(src/**)`).
- **אותה רזולוציה בדיוק** שבה מציירים. דגימה מחדש העלתה את השטח מעל הכביש בעשרות סנטימטרים.
- דחיסה: כימות ל־16 ביט, חיזוי משכנים (שמאל + למעלה − אלכסון), הפרדה לבתים נמוכים וגבוהים, `deflateRaw`, ו־base64. בדפדפן: `DecompressionStream('deflate-raw')`.
- מודול וירטואלי של Vite (`virtual:shimotron-ground`) שמחזיר `null` בבנייה רגילה ואת הנתונים בגרסה המיוחדת.
- **בודקים שהנתונים זהים לחישוב החי**, לפי אזורים. ההבדל שקיבלנו בסוף: מילימטר אחד.

## 3. ייעול קוד הבנייה
- מערכים טיפוסיים וכתיבה ישירה, בלי `array.set([a, b, c])` שמקצה מערך לכל קודקוד. אינדקסים כ־`Uint16Array` או `Uint32Array` ולא מערך JS.
- `Math.sqrt` במקום `Math.hypot` בלולאות חמות.
- לא לחשב אותו דבר פעמיים: לשמור במטמון ערכות שחוזרות בין איים, רק כשהן באמת זהות.
- **להודות כשהשיפור קטן:** "ההבדל נמדד בתוך רעש המדידה".

## 4. מה שאי אפשר לחסוך
- **הכנת השיידרים בכרטיס המסך** קורית בכל מחשב. הדפדפן זוכר אותה, ולכן הפתיחה השנייה מהירה יותר. `compileAsync` מקמפל במקביל, כשיש תמיכה.
- ציור הפריימים הראשונים.

## איך לעשות יותר טוב בפעם הבאה
- **Web Workers:** לבנות כל אי בעובד נפרד. דורש שהנתונים (גבהים, מיקומים) יחושבו בלי DOM ובלי WebGL, ויעברו כמערכים.
- **מטמון IndexedDB:** אחרי הבנייה הראשונה שומרים את הנתונים בדפדפן, עם חתימה. הפעלה שנייה באותו מחשב כמעט מיידית, גם בגרסה באינטרנט.
- **פחות תוכניות שיידר:** חומר אחד גמיש עם פרמטרים, במקום עשרות וריאציות של `onBeforeCompile`.
- **סדר עדיפות:** לבנות קודם את האי שנבחר בתפריט ואת שכניו, ואחר כך את השאר.
- חימום שיידרים בזמן התפריט: לצייר כל חומר פעם אחת מחוץ למסך.
