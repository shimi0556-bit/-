# בונה קורסים אינטראקטיביים — התבנית הקבועה

זה לא סקיל של עקרונות מופשטים — זו התבנית הקונקרטית שהתגבשה בפועל אחרי בניית שלושה קורסים (PowerPoint, Excel, Gmail) לאותו משתמש, שביקש שכל קורס עתידי ייבנה **בדיוק** באותה צורה. `template.html` בתיקייה הזו הוא מנוע העבודה המוכן — SPA בקובץ HTML אחד, עם ניתוב, שאלונים, מעקב התקדמות, דף קיצורים, מבחן מסכם ותעודה, ותיקון back-button מובנה.

## מתי להפעיל

כל בקשה לבנות קורס/מדריך מקיף על תוכנה, אתר או כלי — גם אם לא נאמר המילה "קורס" במפורש ("למד אותי X", "תסביר לי X שלב אחר שלב"). ראה גם את הסקיל `boneh-kursim-visualiyim` בחשבון המשתמש (אם קיים) — הוא מכיל עקרונות איכות כלליים (בדיקה חזותית, מילון מושגים inline וכו') שרלוונטיים גם כאן; הסקיל הזה הוא השכבה הקונקרטית-יותר: **המבנה המדויק** שהמשתמש כבר אישר וביקש לשכפל.

## איך לבנות קורס חדש

1. **העתיקו את `template.html`** ל-`<topic-slug>-course/index.html` (אם עובדים בתוך ריפו כמו זה — תיקייה חדשה ברמת השורש, לצד `powerpoint-course/`, `excel-course/`, `gmail-course/`, עם `README.md` תואם וללא build step).
2. **בצעו את כל ההחלפות המסומנות** בראש הקובץ (`{{TOPIC}}`, `{{TOPIC_SLUG}}`, `{{LOGO_LETTER}}`, `{{TOPIC_EMOJI}}`, וצבעי `--brand`/`--brand-dark`/`--brand-light` — ראו "זהות עיצובית לנושא" למטה).
3. **מלאו את מערך `COURSE`** לפי הסכמה המתועדת בתוך הקובץ: 3 מודולים (מתחילים/בינוני/מקצוענים), כל אחד עם **6-8 שיעורים אמיתיים** (לא פחות — קורס PowerPoint/Excel/Gmail כל אחד הכיל 20-22 שיעורים בסך הכול). לכל שיעור: `content` (HTML — נושא אחד, מדויק, לא lorem), `tip` (טיפ מעשי אחד וספציפי), `quiz` (שאלה + 3 תשובות + הסבר אמיתי לתשובה הנכונה).
4. **מלאו את `shortcuts`** (דף הקיצורים) עם קיצורי מקלדת/פעולות מהירות אמיתיים של הכלי.
5. **בדקו בפועל** לפני מסירה (ראו "בדיקת חובה" למטה) — אל תסתמכו על קריאת הקוד בלבד.

## מבנה תוכן קבוע (לא לשנות בלי שהמשתמש ביקש אחרת)

- **תמיד 3 רמות ברצף אחד**, לא קורס לרמה בודדת — מתחילים ← בינוני ← מקצוענים/מתקדמים.
- כל שיעור: נושא אחד, קצר וממוקד, עם `tip` ו-`quiz` עם משוב מיידי (✅/❌ + הסבר).
- מלבד 3 המודולים: **דף קיצורי מקלדת** (מותאם להדפסה), **מבחן מסכם** על כל שאלות הקורס (סף מעבר: 80%), **תעודת סיום** (עם שם אישי, נפתחת רק אחרי השלמת כל השיעורים, ניתנת להדפסה/PDF).
- **מעקב התקדמות ב-localStorage** (checkbox "הושלם" לכל שיעור + פס התקדמות בתפריט) — נשמר בין ביקורים, מפתחות המפתח (`STORAGE_KEY`/`CERT_KEY`) חייבים prefix ייחודי לנושא כדי לא להתנגש עם קורסים אחרים שנפתחים מאותו דומיין/origin.
- אם לכלי יש "אחים" מאותה משפחה שנראים דומים על פניו (Word/Excel/PowerPoint באופיס, Gmail/Outlook.com/Yahoo Mail וכו') — שיעור אחד (או חלק משיעור, בדרך כלל השיעור האחרון ברמה המקצוענית) מבהיר בקצרה מה באמת משותף לעומת מה שונה בפועל בשימוש. אל תניחו שהדמיון החזותי אומר שהמשתמש כבר מבין את ההבדל.
- **עצמאות טכנית** — קובץ HTML יחיד, בלי build, בלי תלות ברשת. אם עובדים בתוך ריפו קוד — תיקייה עצמאית ברמה של פרויקטים אחרים בריפו, לא רק ארטיפקט מבודד.

## כלל הניווט הקריטי — חיצי הדפדפן

**זה הבאג שכבר תוקן ב-3 הקורסים הקיימים ולא לחזור עליו.** בניווט הפנימי (קליק על שיעור בתפריט, כפתורי הקודם/הבא, קפיצות מכרטיסי הבית) **אסור** להשתמש ב-`location.hash = route` או ב-`history.pushState` — כל קריאה כזו מוסיפה רשומת היסטוריה, וחץ "אחורה" בדפדפן ידפדף פנימה בתוך הקורס במקום לצאת ממנו. המנגנון הנכון (וכבר ממומש ב-`template.html`, פונקציית `navigate()`):

```js
function navigate(route){
  history.replaceState(null, "", "#" + route);
  showRoute(route);
}
```

זה מעדכן את ה-URL בלי רשומת היסטוריה חדשה — לחיצה אחת על "אחורה" יוצאת מהקורס לגמרי. **אל תחליפו את זה בחזרה ל-`location.hash =`** — זו הרגרסיה המדויקת שתוקנה.

## זהות עיצובית לנושא

אל תשתמשו תמיד באותם צבעים. `template.html` מגיע עם סגול ניטרלי כברירת מחדל — **שנו אותו** כך שיתאים לנושא: PowerPoint קיבל כתום/אדום (מיתוג PowerPoint), Excel קיבל ירוק (מיתוג Excel), Gmail קיבל אדום/כחול (מיתוג Google). בחרו צבע שמזוהה עם הכלי עצמו כשקיים כזה, אחרת פלטה נקייה ומקצועית שמתאימה לאופי הנושא.

## בדיקת חובה לפני מסירה

לא מספיק לוודא שהתגיות מאוזנות. להריץ בפועל (headless browser או שקול):
1. פתיחת הקובץ + `node --check` על ה-JS המופק (לתפוס תקלות תחביר כמו `` ` `` לא-escaped בתוך template literal, או `<p">` שגוי).
2. ניווט דרך כמה שיעורים, מענה על שאלון אחד, וידוא שההסבר מוצג ושה"הושלם" מסתמן.
3. **בדיקת חץ אחורה**: לדפדף בין כמה שיעורים ואז ללחוץ "אחורה" בדפדפן פעם אחת — התוצאה חייבת להיות יציאה מהקורס, לא חזרה לשיעור הקודם.
4. מענה על כל שאלות המבחן המסכם ווידוא שהציון מחושב נכון.
5. וידוא שהתעודה נפתחת רק אחרי השלמת כל השיעורים.

## אחרי הבנייה

- לעדכן את `README.md` הראשי של הריפו (אם רלוונטי) עם שורה חדשה בטבלת הפרויקטים.
- לשלוח את הקובץ למשתמש ישירות (לא רק לינק ל-PR/ריפו) — המשתמש ביקש את זה במפורש בעבר.
- אם מבצעים תיקון מנגנון (כמו תיקון ה-navigate) על קורס קיים — להחיל אותו על **כל** הקורסים הקיימים בריפו, לא רק על האחד שהוזכר, כדי לשמור על עקביות.
